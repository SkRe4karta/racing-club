## 1. Описание и назначение системы

**АИС «Скачки»** предназначена для автоматизации учета и просмотра сведений о состязаниях клуба любителей скачек, участвующих лошадях, их владельцах, жокеях и результатах заездов.

### Ключевые возможности первой версии (v1.0):
1. **Реестр владельцев**: регистрация владельцев лошадей (ФИО, адрес, телефон) и просмотр карточек владельцев со списками принадлежащих им лошадей.
2. **Реестр лошадей**: учет зарегистрированных лошадей (кличка, пол, возраст, владелец) и карточки лошадей со сквозной историей выступлений в состязаниях.
3. **Реестр жокеев**: учет профессиональных жокеев (ФИО, адрес, возраст, рейтинг) и карточки жокеев с историей заездов.
4. **Будущие состязания**: планирование заездов (наименование, дата, время, ипподром) с предварительным формированием списка заявленных пар «лошадь — жокей».
5. **Прошедшие состязания и фиксация результатов**:
   - Завершение ранее запланированного состязания: ввод показанного времени либо отметка дисквалификации для каждого участника;
   - Автоматический расчет мест по возрастанию времени финиша (дисквалифицированным участникам место не присваивается);
   - Защита результатов: после перевода в статус «Завершено» состязание переходит в архив, изменение протокола заблокировано;
   - Создание состоявшегося состязания «в один проход» сразу со списком результатов.
6. **Защита целостности данных и обработка ошибок**:
   - Запрет повторного добавления одной и той же лошади или одного и того же жокея в рамках одного состязания;
   - Контроль корректности форматов времени, возраста и обязательных полей;
   - Понятные сообщения об ошибках и страницы 404/500 без технического стектрейса.

## 3. Архитектура и структура базы данных

Логическая модель включает 5 основных сущностей:
- `Owner` (Владелец): `id`, `full_name`, `address`, `phone`.
- `Horse` (Лошадь): `id`, `nickname`, `gender`, `age`, `owner_id` (внешний ключ к `Owner`).
- `Jockey` (Жокей): `id`, `full_name`, `address`, `age`, `rating`.
- `Competition` (Состязание): `id`, `title`, `event_date`, `event_time`, `location`, `status` (`'planned'` / `'completed'`).
- `Result` (Участник / Результат): `id`, `competition_id`, `horse_id`, `jockey_id`, `finish_time_seconds`, `is_disqualified`, `place`.
  - Уникальные индексы: `(competition_id, horse_id)` и `(competition_id, jockey_id)`.

```
[ Owner ] 1 ───< N [ Horse ]
                       │
                       v
[ Competition ] 1 ───< N [ Result ] >─── 1 [ Jockey ]
```

## 5. Инструкция по локальному запуску

### Шаг 1. Клонирование репозитория / переход в директорию проекта
```bash
cd d:\Programming\cycle
```

### Шаг 2. Создание и активация виртуального окружения
```bash
# Windows:
python -m venv venv
.\venv\Scripts\activate

# Linux / macOS:
python3 -m venv venv
source venv/bin/activate
```

### Шаг 3. Установка зависимостей
```bash
pip install -r requirements.txt
```

### Шаг 4. Наполнение базы данных демонстрационными данными (рекомендуется для сдачи)
Скрипт создает таблицы и наполняет базу реалистичными тестовыми записями (владельцы, лошади, жокеи, завершенные и запланированные заезды):
```bash
python seed.py
```

### Шаг 5. Запуск веб-приложения
```bash
python run.py
```
После запуска откройте в любом современном веб-браузере адрес:  
👉 **http://127.0.0.1:5000**

## 6. Проверка соответствия ТЗ (Приемочные испытания)

Для автоматизированной проверки всех 10 обязательных сценариев приемки (раздел 6.1 ТЗ) выполните команду:
```bash
python -m unittest verify_acceptance.py
```
Все 9 сценариев тестов выполняются успешно:
1. `test_1_add_owner_and_view` — Добавление владельца и отображение в списке.
2. `test_2_add_horse_and_detail` — Добавление лошади с выбором владельца и открытие карточки.
3. `test_3_add_jockey_and_detail` — Добавление жокея и открытие карточки.
4. `test_4_future_competition_creation_and_listing` — Планирование будущего состязания с парами «лошадь-жокей» и отображение только в будущих.
5. `test_5_and_6_complete_competition_and_calculate_places` — Завершение состязания, ввод времени, автоматический расчет мест (1, 2, 3...) и отсутствие места у дисквалифицированного.
6. `test_7_no_edit_after_complete` — Запрет последующего изменения результатов завершенного заезда.
7. `test_8_add_past_competition_direct` — Добавление состоявшегося состязания «в один проход».
8. `test_9_horse_and_jockey_history` — Отображение истории состязаний в карточках лошади и жокея.
9. `test_10_validation_and_error_handling` — Корректная обработка некорректного ввода и блокировка дубликатов участников.
