Результат: **10 пройдено, 0 ошибок, 0 провалов, 0 пропущено**, 2.061 s.
Каждый тест создавал отдельную `racing_test_<uuid>` БД и удалял только её.
Локальная trust-аутентификация ограничена Unix-сокетом в приватном временном
каталоге; TCP выключен. Этот адрес временный и не является конфигурацией приложения.

Состав десяти проверок:

1. Регистрация OWNER с новым связанным профилем.
2. Регистрация JOCKEY, новый профиль и начальный рейтинг 0.
3. Регистрация VIEWER без спортивного профиля.
4. Вход, последний вход, защита страницы аккаунта.
5. OWNER: запрет подмены owner_id и разрешение создания собственной лошади.
6. ADMIN: создание и завершение старта, запрет управления профилями.
7. CSRF: отсутствие/подделка, чужая сессия, устаревший токен, ротация при входе.
8. Общий лимитер: 16 параллельных обращений через два приложения, ровно 5 допущены.
9. Adopt/upgrade v1.1: сохранение всех полей записей пяти таблиц, уникальности
   участников, публичных страниц, результата CSV; `db check` без расхождений.
10. Регрессия: поиск кириллицей, фильтры, сортировка, пагинация и крайние параметры.

Реально запущен Gunicorn 25.3.0 с `--preload --workers 2` на loopback и временной
SQLite после миграций. `/health` вернул 200 и выполнил SQL. Прежний seed отработал
на пустых спортивных таблицах; он не создаёт аккаунты.

Chrome через Playwright: публичная форма создала OWNER, выполнен вход, открыт
собственный аккаунт и форма лошади с единственным разрешённым владельцем,
POST-выход, вход ROOT и открытие защищённой формы владельца. Пароль ROOT сгенерирован
во время проверки, передан в скрытый CLI prompt, не попал в исходники/лог.
Проверены ширины 1440, 390 и 320 px, закрытие мобильной навигации, отсутствие
переполнения документа и панели; ошибок JavaScript — **0**. После добавления
кнопок аккаунта скорректирована высота панели на узких экранах. Скриншоты и логи
остались в /tmp, в Git не включены. Временный Gunicorn остановлен.

## Безопасность и ограничения среды

В production-конфигурации нет глобального отключения CSRF, debug и автоматического
DDL. Cookies Secure/HttpOnly/SameSite, хеши scrypt, server-side allowlist ролей,
проверка статуса и принадлежности, общий DB rate limit и защита от повторного
ROOT. Скрытие кнопок дополнено защитой прямых HTTP-запросов. Параметры SQL скрыты
в диагностике, публичные ошибки не показывают traceback. Проверены список файлов
и шаблоны секретов; .env, БД, кэши и .venv не включены в изменения.

Dockerfile и Compose YAML проверены статически: PostgreSQL 18, сохранённый том,
передача cookies-конфигурации, включение migrations в образ. **Сборка Docker и запуск
Compose не выполнялись**: Docker socket недоступен текущему пользователю даже вне
sandbox, плагин `docker compose` отсутствует. Для независимой приёмки выполнить
контейнерные команды из ALPHA1.md на отдельном Docker-хосте. Это ограничение среды,
а не подтверждённый результат контейнерной сборки.

Не создавались PR/merge, не менялись master/dev/prod, legacy использован только как
историческая ссылка. Большой генератор, кабинеты, заявки и остальные этапы не начаты.
