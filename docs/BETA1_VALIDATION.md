### Содержание и исправления

Семь новых SQLite-сценариев охватывают полный набор/5 ролей; 10 публичных страниц
с пределом <40 SQL-запросов/<650 загруженных объектов, поиск и страницу 2;
7 вариантов неоднозначной/рабочей конфигурации; 2 вида непустой БД (только аккаунт
или только throttle); существующий accounts, запрещённый путь и rollback;
две воспроизводимые генерации и два отказа повторного заполнения;
две намеренные порчи (чужое личное согласие и будущая оценка) с обнаружением.

Семь сохранённых SQLite-сценариев: CSRF/ротация; отключённая сессия;
подмена owner_id; HTTP-матрица административных ролей/методов;
заявка→личные согласия→допуск; ничьи/DNF/DSQ; смена пароля/отзыв старых сеансов.
Тесты безопасности сохраняют включённый CSRF. Прежние тесты не удалялись/не ослаблялись.

Пять PG-сценариев: чистая установка/metadata/ROOT-вход; upgrade v1.1 с сохранением
записей; small-импорт и 3 настоящих нарушения UNIQUE/FK/CHECK с rollback;
конкурентное создание одного прогноза (два потока, один победитель);
upgrade заполненной Alpha 3→0005 с сохранением прежних данных. Использовались
только случайные временные БД, удалённые штатным isolated_database.

1. SQLite при большом импорте блокировал вспомогательное соединение инспекции.
   row_counts теперь читает схему через то же соединение транзакции; повтор
   большого импорта/целостности прошёл.
2. В новом HTTP-тесте долгоживущий app_context сохранял Flask-Login g после
   db.session.remove, вызывая DetachedInstanceError/503. Fixture теперь очищает
   пользователя перед каждым запросом, как при настоящем HTTP. Повтор целого
   сценария не запускался сверх лимита. ROOT/ADMIN/OWNER/JOCKEY/VIEWER страницы
   адресно подтверждены отдельными реальными запросами в единственном browser smoke.
   Это ошибка тестового fixture, изменения production-аутентификации не требовались.
3. Исправлены два имени PG-классов в выбранном suite; их тела прошли адресно.
4. Smoke ошибочно запросил `/root/audit`. В приложении штатный `/admin/audit`;
   дополнительная съёмка артефакта этой страницы получила HTTP 200. Утилита съёмки
   затем ошиблась Python context manager APIResponse при выводе `/health`;
   снимок уже сохранён, это не дополнительный функциональный прогон. `/health`
   ранее прошёл в основном browser smoke. Эти ошибки обвязки не скрываются.

Не достигнутые из-за остановки части assertions нового HTTP-теста (SQL-пределы
всех приватных страниц и сравнение двух реализаций account_accuracy) не объявляются
выполненными. Реальные приватные страницы/итоги/формы проверены браузером;
оценки всех прогнозов независимо проверены validate. Полный регрессионный и
performance-прогон, измерение покрытия и все комбинации фильтров не выполнялись.

### Причины двух прежних ошибок

1. **SQLite HTTP fixture:** большой тест держал app_context между HTTP-запросами.
   Flask-Login сохранял User в g, а db.session.remove отсоединял/истекал этот ORM
   объект. Следующий запрос получал DetachedInstanceError/503. Это дефект фикстуры,
   а не прав доступа приложения. Исправление: каждый запрос test client создаёт
   собственный app context; cleanup большого fixture зарегистрирован заранее.
   Удалён временный before_request-hook очистки g. Аутентификация и ожидаемые
   ответы не ослаблялись. Тот самый test_bounded_pages_queries_and_accuracy
   теперь полностью прошёл: все роли, приватные SQL-пределы и сравнение двух
   расчётов account_accuracy действительно выполнены.
2. **Browser harness:** /root/audit не зарегистрирован; реальная страница аудита —
   /admin/audit. Новый воспроизводимый scripts/browser_smoke.py использует правильный
   URL и прошёл настоящий ROOT-вход/страницу. Проверка HTTP 200 сохранена.
   Прежние неверные имена PostgreSQL-классов уже исправлены; ошибок загрузки
   в текущем раунде нет. Ограничения окружения здесь не маскируют дефект приложения.
