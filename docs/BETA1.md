# Racing Club 2.0.0-beta.1

Разработано поверх принятой Alpha 4 `ce3b380a1e6da8306c598e7f6d0734908003b7f2`
в `feature/v2-alpha-1-foundation`. Повторная локальная ручная приёмка исправленной
Beta 1 подтверждена пользователем 16.10.2026. Commit/push разрешены только в
`origin/feature/v2-alpha-1-foundation`; PR/merge и серверные окружения в разрешение не входят.

## Генератор

`seed.py` — явная CLI; `app/demo.py` — внутренний исторический импорт, не HTTP API.
Схема не меняется: Alembic head — `0005_predictions`. Все прежние миграции сохранены.
Обычные спортивные операции продолжают проверять текущие сроки; импорт создаёт
синтетическую историю отдельно, сохраняя CHECK/FK/UNIQUE, личные согласия и аудит.

Режимы `small` и `full`; по умолчанию full, seed=20261016, as-of=текущая дата.
Спортивное содержание повторяется при одинаковых размере, seed, дате и версии кода.
Пароли и соли **всегда новые**, поэтому БД побайтно не повторяется. Отчёт содержит
SHA256 содержимого без хешей паролей, last_login_at и auth_throttles. Это проверка
повторяемости в одной СУБД; формат datetime в fingerprint разных СУБД может отличаться.

Все аккаунты активны, email — зарезервированный домен `example.test`, контакты
синтетические. ФИО, клички, ипподромы и соревнования имеют естественные названия
без технических приставок/суффиксов и общей нумерации этапов. Это вымышленная
история, не реальные исторические соревнования; признак происхождения сохраняется
служебным событием `demo_initialized`. Случайный пароль каждого
аккаунта хешируется scrypt. Первый VIEWER имеет оба режима прогнозов во всех стартах.
Ни пароли, ни ключ сессии в аудит/отчёт/дамп не записываются.

### Безопасные условия

Генератор **не читает DATABASE_URL**. Требуется отдельная переменная
`RACING_DEMO_DATABASE_URL`. Для PostgreSQL допустим только драйвер `postgresql+psycopg`
и имя БД с префиксом `racing_demo_`; SQLite — абсолютный путь с именем `racing_demo_…`
вне репозитория. Один префикс не является разрешением использовать рабочую БД:
оператор обязан создать новую отдельную БД. Генерация требует `--confirm-demo`.

БД должна быть уже мигрирована, иметь только известные таблицы и актуальную ревизию.
Все прикладные таблицы, включая users, audit_logs и auth_throttles, должны быть пусты.
Проверка выполняется под блокировкой: PostgreSQL advisory + table locks, SQLite
BEGIN IMMEDIATE. Запускайте импорт до старта web. Одно соединение/транзакция на
импорт; ORM пакетно сохраняет записи по соревнованиям. Отдельных HTTP-запросов нет.

Файл `--accounts` должен быть новым и находиться вне репозитория. O_EXCL/O_NOFOLLOW
не позволяют перезаписать существующий файл/символическую ссылку; права — 600.
Создавайте родительский каталог с правами 700. Файл синхронизируется до commit;
при штатной ошибке вся транзакция откатывается и удаляется только созданный этим
запуском файл. При аварийном завершении ОС до commit может остаться неполный файл:
сначала проверьте БД и используйте новый путь. Файл не является резервной копией БД.

**Reset отсутствует.** Ни DELETE, ни TRUNCATE, ни drop_all генератор не выполняет.
Для повторной генерации создайте другую пустую `racing_demo_…` БД и другой файл
аккаунтов. Нет подтверждения, способного разрешить очистку STAGE/PROD.

### Пример PostgreSQL 18

Только на локальном/одноразовом сервере, не на STAGE/PROD:

```bash
umask 077
mkdir -m 700 /tmp/racing-beta1-example
createdb racing_demo_beta1_example
export RACING_DEMO_DATABASE_URL='postgresql+psycopg:///racing_demo_beta1_example'
export DATABASE_URL="$RACING_DEMO_DATABASE_URL"
# SECRET_KEY должен быть задан для Flask; генератор не использует ключ приложения.
flask --app run db upgrade
python seed.py generate --size full --seed 20261016 --as-of 2026-10-16 \
  --confirm-demo --accounts /tmp/racing-beta1-example/accounts.txt
python seed.py validate
python seed.py counts
```

Для отдельного SQLite-сценария замените URI на
`sqlite:////tmp/racing-beta1-example/racing_demo_beta1.sqlite`.
Сайт запускается с DATABASE_URL этой же БД; даты на сайте сравниваются с реальным
временем. Для демонстрации сегодня опускайте `--as-of`; фиксированная дата нужна
для воспроизводимой истории и со временем перестанет отражать текущий календарь.
Не выполняйте create-root после генерации: единственный ROOT уже создан.

### Состав и история

| Категория | small | full |
| --- | ---: | ---: |
| Пользователи | 46 | 360 |
| Владельцы | 14 | 140 |
| Жокеи | 16 | 80 |
| Лошади | 40 | 330 |
| Завершённые / будущие старты | 15 / 3 | 150 / 30 |
| Заявки | 140 | 2200 |
| Официальные участия results | 87 | 1680 |
| Из них завершённые выступления | 75 | 1500 |
| Прогнозы | 260 | 2600 |

События, выборы, уведомления и аудит создаются по фактической цепочке; их больше
первоначальных ориентиров. Полные числа текущей демонстрации — в
[BETA1_VALIDATION.md](BETA1_VALIDATION.md).

Завершённые старты распределены на 730 предыдущих дней, будущие — на дни +7…+123.
Это двухлетнее окно, которое пересекает три календарных года; не искусственно
усечённые два календарных сезона. Пять дистанций, четыре условных ипподрома,
различные времена и 8–12 исторических участников (4–8 будущих).
Есть жеребцы/кобылы/мерины, одиночные и крупные конюшни, лидеры с многолетней
историей, лошади без побед и три молодые лошади без официальных участий.
Возраст записан на опорную дату; историческим лошадям не менее трёх лет.

Согласование начинается OWNER или JOCKEY; второй подтверждает лично. ADMIN
утверждает, создаётся связанный официальный Result с уникальным стартовым номером.
Ожидающие заявки не становятся участниками. Отклонения и отмены предшествуют
новым допускам; три вида ожидания есть только у будущих соревнований.
ROOT участвует в двух документированных изменениях аккаунта и контролируемых
коррекциях, сохраняющих полные снимки. Личные согласия за стороны он не даёт.

Финиши, разделённые места (1,1,3…), DNF/DSQ проходят prepare_protocol; прогнозы
оценивает штатный assess_predictions. Исторические временные отметки фиксируются
по моментам публикации/коррекции. Будущие участия без места/времени, прогнозы pending.
Оба режима содержат правильные/неправильные выборы и неоднозначные позиции при ничьей.
Финансовых сущностей нет.

### Проверка целостности

`validate` только читает данные. Проверяет каждую FK, пары/стартовые номера,
вместимость, сроки/возраст/статусы, личные согласия и административное решение,
связь допуска, места по времени, диапазон времени по дистанции, DNF/DSQ,
источник уведомлений, полные коррекции ROOT, время и оценку каждого прогноза.
Оценка вычисляется независимо от записанных полей. При несогласованности — ненулевой
код; подробная программная ValueError содержит только названия проверок и ID.
CLI скрывает исключения драйвера, чтобы не раскрывать параметры подключения.

## Работа с большой историей

Карточки лошади/жокея и спортивный кабинет: 20 участий на страницу, SQL-итоги за
весь выбранный период и последние 24 завершённых выступления для графика.
Среднее время по дистанции считается по всему периоду, а не текущей странице.
Карточки собственных лошадей используют групповые SQL-агрегаты.
Кабинет показывает до 12 приглашений, 6 будущих участий/регистраций, 5 уведомлений;
полная история заявок и уведомлений доступна через существующую пагинацию.
История прогнозов больше не загружает все Prediction/Choice ради точности:
две SQL-агрегации дополняют страницу из 20 прогнозов. CSV протокола подгружает
лошадей/жокеев пакетно. Каталоги/рейтинги сохраняют свои фильтры и пагинацию.

## Уточнения после ручной проверки Beta 1 — 16.10.2026

`app/demo_names.py` формирует сезонные названия и условные ипподромы, не расходуя
спортивный random generator. Название учитывает месяц/год, сезон и дистанцию:
«Осенний кубок», «Большой приз октября», «Приз выносливости», «Кубок спринтеров».
ФИО/клички не содержат [демо], контакты не заменяются чужими реальными адресами.
Все 180 названий полного набора различимы без сквозной технической нумерации.

Обычный `generate` по-прежнему **никогда не обновляет непустую БД**. Для текущей
ручной демонстрации выполнена отдельная согласованная операция только в
`racing_demo_beta1_review` на прежнем локальном Unix socket. Перед ней проверены
точный URI/имя, marker full/seed/as-of, состав аккаунтов и прежние сгенерированные
названия; создан приватный pg_dump. Изменены только подписи, адреса-заглушки и
тексты уведомлений. ID, спортивные поля/условия, revision, заявки, события,
результаты, прогнозы и выборы сохранены (сравнены SHA256 до/после под блокировкой).
Прежний append-only аудит не переписан; добавлен `demo_labels_refreshed`.
Эта разовая процедура не добавлена в CLI и не применяется к другим БД.

`/competitions/` — единая точка входа, по умолчанию view=future.
`view=past` показывает завершённые старты, `view=calendar` — оба статуса.
Старые маршруты списков используют ту же реализацию. Поиск, дата, место,
сортировка, количество, страницы по 20 и CSV сохранены. Количество официальных
участников вычисляется SQL COUNT, без загрузки Result/Horse/Jockey для каждой строки.
Календарь фильтрует запрос по границам месяца, различает статусы текстом/значком,
поддерживает несколько событий на день, выбор дня/месяца/года и возврат из
карточки к выбранной дате. На телефоне используются компактные ✓/●, легенда,
доступные названия ссылок и полная подборка событий выбранного дня.

Ошибка HTTP-фикстуры исправлена отдельным app context на **каждый** запрос,
без обхода политики доступа или изменения ожидаемых ответов. Браузерная проверка
перенесена в репозиторий и обращается к настоящему `/admin/audit`.
Фактические результаты текущего раунда — в последнем разделе BETA1_VALIDATION.md.
