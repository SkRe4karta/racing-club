## Исходное состояние и объём

Проверены cwd, чистота исходного рабочего дерева, ветка, remotes и включение принятого
Alpha 2 через `git merge-base --is-ancestor`. `git ls-remote origin

и dev `130dcb277fbed9f102fd02d45bd4fef4d784f2d6`. Чтение origin выполнено после

Реализованы ADMIN/ROOT, пустое создание/редактирование соревнования, допуск,
официальные номера и происхождение Result, завершение/DSQ/DNF/ничья, контролируемая
коррекция ROOT, пользователи/привязки, аудит и согласованные уведомления.
ROOT не выдаёт свои действия за личное согласие. Старыми ROOT-согласиями из Alpha 2
нельзя обосновать допуск; их не удаляют. Даже старую заявку с ROOT-инициатором нельзя
отменить обычной кнопкой без причины: используется отдельная аудируемая операция.

Старые тесты записи адаптированы к новой процедуре, а не к открытому обходу.
В тестах чтения legacy-протоколов используется явный изолированный fixture v1.1;
производственные сервисы прямой записи проверяются как запрещённые.
Сохранены 32 проверки авторизации, 37 Alpha 2 и 19 функциональных регрессий.

## Конкурентные проверки непосредственно на PostgreSQL

Эти же тесты фактически выполнены на PostgreSQL 18.6, не заменены SQLite:

- четыре допуска одной заявки через два приложения и двух разных ADMIN:
  ровно один Result, один аудит, одна пара уведомлений о допуске;
- две пары претендуют на последнее место: допущена одна;
- ручное ROOT-исключение конкурирует с заявкой по той же лошади:
  конфликтующая ручная пара не попадает в официальный список;
- четыре публикации через два разных ADMIN: ровно один completed-протокол,
  одна запись аудита и одно уведомление каждому участнику;
- четыре блокировки аккаунта: одно изменение, один аудит, одно уведомление;
- прежние конкурентные подачи/согласования Alpha 2 и межпроцессный auth throttle.

Для явной одновременности в ключевых новых сценариях используются барьеры потоков.
Сериализация PostgreSQL — блокировки строк и условные обновления, SQLite — revision/CAS.

## Миграции и сохранность

Новая ревизия: `0004_administration`. Описание полей и установки — ALPHA3.md.
Исторические ревизии `0001`–`0003` не менялись: `git diff --exit-code HEAD --
migrations/versions/0001_v11_baseline.py migrations/versions/0002_auth_foundation.py
migrations/versions/0003_applications_applications_and_notifications.py` вернул 0.
Миграция просмотрена вручную; модель не импортируется, старые значения не переписываются.
SQLite batch-операции копируют записи двух таблиц при добавлении ограничений;
приложение не очищает БД и не выполняет DDL при запуске.

На обоих движках проверены чистый upgrade, повторный upgrade, соответствие ORM
(`db check`: `No new upgrade operations detected`), FK/CHECK/UNIQUE и запрет downgrade.
Проверено усыновление пяти таблиц v1.1, сохранение всех их прежних полей/результатов,
обновление Alpha 1 с аккаунтами/хешами/счётчиками и обновление **заполненной Alpha 2**.
Последнее сравнивает до/после все прежние столбцы девяти таблиц, включая Application,
ApplicationEvent и Notification с FK на событие. Новые поля legacy Result остаются
NULL/false. Проверена генерация PostgreSQL offline SQL, без DROP TABLE.

Рабочий DATABASE_URL не используется. Каждый тест владеет собственной временной
SQLite либо случайной `racing_test_<uuid>` PostgreSQL-БД. Новый кластер расположен
в `/tmp/racing-alpha3-pg-c9hgwz__`, PostgreSQL **18.6**, только приватный Unix-сокет,
TCP выключен, peer-аутентификация локально, host-вход запрещён. После итогового
прогона read-only запрос подтвердил **0 оставшихся racing_test_* БД**. Кластер
остановлен после проверки. STAGE/PROD, рабочие БД и Docker-тома не затрагивались.

Sandbox запрещает создание/подключение сокетов (`Operation not permitted`);
запуск временного PostgreSQL и полноценные PostgreSQL-прогоны выполнены с разрешённым
выходом из sandbox. Первые заблокированные попытки не засчитаны успешными тестами БД.

Браузер реально создал новое соревнование без участников, OWNER отправил заявку,
JOCKEY лично подтвердил, ADMIN допустил, публичная страница показала пару.

Это ограниченная браузерная проверка, не полный аудит доступности всех устройств.
